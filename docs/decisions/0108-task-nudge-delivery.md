# ADR 0108: task nudge delivery is a one-attempt durable slot

Status: integrated in the local staging branch, not accepted for deployment. Renumbered after the core ADRs.

Task nudges are separate from personal assistant reminders. Each guild-scoped slot has a stable key for a due-date-specific 48-hour reminder, a custom time, a weekly task check-in, a weekly subteam digest, or a reply follow-up. The producer scans at startup and once a minute; slots survive a restart in SQLite. Existing task team announcements channel determines each subteam digest destination. Custom times can be supplied at owner task creation or appended by the owner later. Time keys use Pacific calendar weeks, even if the task's due timezone differs.

The daemon checks Pacific quiet hours, midnight to 8am by default, before claiming due slots. The owner can configure a per-guild quiet-hours override through MCP; absent that row, the Pacific environment default applies. The disabled-by-default send switch is operator configuration, not member-settable. Planning mode records planned deliveries and does not send. Each claimed slot is settled with exactly one audit row; moved, deleted, or inaccessible destinations pause; a stale due-date slot is superseded. A claimed slot whose send outcome is unknown after a crash is paused, not blindly resent, because the Discord send API has no idempotency token. Operators must reconcile ambiguous outcomes manually. This favors avoiding duplicate posts over guaranteed delivery.

Before sending, the worker fetches the category and channel live. A thread must still be under the team's category, open, and unlocked. Text is stripped of live mention tokens and Discord allowed mentions are empty. A member reply to the sent reminder is recorded and queues one follow-up only when it references the reminder in its original destination and the author still has the task's membership or assignment. The follow-up itself does not mark a task complete or approve it. No task send is activated until identity/approval work and a test-guild run have been reviewed.
